# 運用ガイド — UPSIDER残額共有アプリ

このドキュメントは、施設スタッフ・adminとしてこのアプリを日常運用する方向けのガイドです。開発者向けの技術ドキュメントは [docs/design/](../design/) と [docs/rules/](../rules/) を参照してください。

## 1. 共用端末でのログイン運用

このアプリは施設ID/PASS・admin ID/PASSともに**長期セッション**（Firebase Authの標準機能により、数週間〜数ヶ月ログイン状態が保持される）を採用しています。共用のPC・タブレットにログインしたまま使い続けられる利便性を優先した設計ですが、その分、端末の管理には注意が必要です。

### 基本ルール
- **施設の共用端末を最後に使う人（最後の退勤者など）は、ダッシュボード画面の「ログアウト」ボタンを押してからその場を離れてください。** 特に、店舗外に持ち出し可能なノートPC・タブレットで使う場合は必須です。
- 固定設置されたレジ横のPCなど、施設外に持ち出されない端末であれば、営業時間中はログインしたままで運用して構いません。
- 端末を廃棄・譲渡・修理に出す前には、必ずログアウトしてください。

### admin端末は特に注意
adminアカウントは残額の直接編集・購入履歴の削除など強い権限を持ちます。admin用のログインを行う端末（通常は施設責任者のPCやスマートフォンを想定）は、以下を徹底してください。

- **施設ID/PASSより強固なパスワードを設定する**（第三者が推測しにくい、他のサービスと使い回さない）。
- 私物のスマートフォン等でadminログインする場合、その端末自体に画面ロック（PINコード・生体認証等）を設定する。
- 端末を紛失・盗難した場合は、速やかに次章の「緊急時の対応」を実施する。

## 2. パスワードの取り扱い

- 施設IDは「施設内で共有する情報」として扱って構いません（IDそのものは秘密にする必要はありません）。実際の防御はPASSの強度に依存します。
- admin IDおよびPASSは、施設の責任者など限られた人だけが知る状態を維持してください。
- パスワードの変更や、新しいスタッフ用アカウントの発行は、システム管理者（開発担当）に依頼してください。現状、アプリ内にセルフサービスでのパスワード変更機能はありません（意図的な設計、[README.md](../../README.md)参照）。

## 3. 緊急時の対応（端末紛失・盗難時）

共用端末やadminログイン済みの端末を紛失・盗難された場合、以下の手順でセッションを強制的に無効化できます。この作業はシステム管理者（Firebase Consoleへのアクセス権を持つ人）が行います。

### 手順（Firebase Console）
1. https://console.firebase.google.com/project/upsider-balance/authentication/users にアクセス
2. 該当のアカウント（施設なら `<施設ID>@facility.upsider-balance.local`、adminなら `<adminID>@admin.upsider-balance.local`）を探す
3. 該当ユーザーの行の「⋮」（その他のオプション）メニューから「アカウントを無効にする」を選択

   - これにより、そのアカウントでの新規ログイン・既存セッションでのAPIアクセスの両方がすぐにブロックされます。
4. 状況が落ち着き、新しいパスワードでの運用を再開したい場合は、開発担当に依頼して新しいアカウントを発行するか、無効化したアカウントを再度有効化してパスワードをリセットしてください（Firebase Consoleの「パスワードをリセット」機能、またはシステム管理者による`scripts/create-account.ts`を使った再発行）。

### 補足：なぜ「ログアウト操作」だけでは不十分か
紛失した端末側で明示的にログアウト操作をすることはできない（端末が手元にない）ため、リモートから強制的に無効化する上記の手順が必要です。Firebase Authのリフレッシュトークンは、パスワード変更やアカウント無効化を行わない限り有効であり続けます（長期セッションの設計上の特性）。

## 4. トラブル発生時の相談先

アプリの動作不具合、ログインできない等の技術的な問題は、システム管理者（開発担当）に連絡してください。開発中に発生した既知の問題とその対応は [docs/troubleshooting/00_troubleshooting_log.md](../troubleshooting/00_troubleshooting_log.md) に記録されています。
