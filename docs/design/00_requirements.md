# 要件定義書 — UPSIDER残額共有アプリ

## 1. 背景・目的
UPSIDERカード（法人カード）の残額をスタッフ全体で共有し、購入のたびに残額を減算していくことで、施設内の残額をリアルタイムに把握できるようにする。

## 2. スコープ
- 単一施設での利用（マルチテナント対応は将来検討、今回は非対応）
- スタッフ個人の識別は行わない（施設単位のログインのみ）

## 3. ユーザーロール
| ロール | ログイン方法 | 主な操作 |
|---|---|---|
| スタッフ（施設共用アカウント） | 施設ID + PASS | 残額確認、購入登録（金額入力・レシート画像解析）、購入履歴閲覧 |
| admin | admin専用ID + PASS（施設アカウントとは別体系） | 残額の初期設定・修正、購入履歴の編集・削除、（将来的な設定機能の拡張） |

- スタッフ個人の識別・記録は行わない。「誰が購入したか」は保存しない。
- 設定画面はスタッフ向けには提供しない。すべての管理操作はadminページに集約する。

## 4. 機能要件

### 4.1 認証
- 施設ログイン：施設に一意なID/PASSでログイン。スタッフ個別アカウントなし。
- adminログイン：施設ログインとは完全に別のID/PASS・別ロールとして管理。
- セッションは長期保持（共用端末想定）。有効期限は数週間〜数ヶ月オーダー。
- パスワードはハッシュ化して保存（平文保存禁止）。

### 4.2 残額管理
- 現在残額を画面上に大きく表示。
- 初期残額はadminがベタ入力（手打ち）で設定・修正可能。
- スタッフは「購入登録」から金額を入力すると、残額から自動減算される。
- 残高がマイナスになる購入も一旦許容する（実際にカードで使えてしまった場合の記録目的）が、UI上で警告表示する。

### 4.3 購入登録・履歴
- スタッフが購入金額（必須）、購入品目メモ（任意）、購入日時（デフォルト現在時刻）を入力して登録。
- 登録すると同時に残額から減算し、購入履歴に1件追加。
- 購入履歴一覧をスタッフ全員が閲覧可能（誰が購入したかは記録しない・表示しない）。
- 履歴の編集・削除はadminのみ可能（スタッフ画面には編集・削除ボタンを出さない）。

### 4.4 レシート画像解析（Phase 2想定、設計には含める）
- スタッフがレシート写真をアップロード。
- Gemini Vision APIを用いて、購入金額・店舗名・品目候補を抽出。
- 抽出結果をフォームにプリフィルし、スタッフが確認・修正してから登録（自動登録はしない＝誤読対策）。
- 解析元画像はFirebase Storageに保存し、購入履歴から参照できるようにする。

### 4.5 admin機能
- 残額の直接編集（現在値の上書き、増減）
- 購入履歴の編集・削除
- （将来拡張の余地は残すが、今回は上記以外の設定項目は作らない）

## 5. 非機能要件
- コスト最小化：Firebase無料〜低額枠に収まる設計（Spark→必要に応じてBlazeの従量課金のみ）。独自ドメイン不要。
- 対応端末：スマホ・タブレット・PCブラウザ（レスポンシブ）。共用端末での利用が主。
- 可用性：個人利用規模のため高度な冗長化は不要。Firebaseマネージド機能に依存してよい。

## 6. セキュリティ要件（詳細は 01_security_design.md）
- 施設ID/PASSおよびadmin ID/PASSは平文で保存・送信しない。
- 施設ロールとadminロールを明確に分離し、権限昇格を防ぐ。
- 購入履歴・残額データへの書き込みはFirestoreセキュリティルール／Cloud Functions経由のみで許可し、クライアントから直接の不整合な書き込みを禁止する。
- レシート画像はアップロードした施設のみアクセス可能とする。

## 7. 技術スタック
- フロントエンド：SvelteKit
- バックエンド：Hono（Cloud Functions for Firebase上で稼働、もしくはCloud Run）
- DB：Firestore
- 認証：Firebase Authentication（カスタムトークン or カスタム実装、詳細は設計書で決定）
- ストレージ：Firebase Storage（レシート画像）
- 画像解析：Gemini Vision API（Vertex AI経由 or Gemini API）
- ホスティング：Firebase Hosting（無料サブドメイン）

- Cloud FunctionsとHonoの具体的なルーティング構成
