# コスト試算書 — UPSIDER残額共有アプリ

前提：単一施設、利用者は施設内スタッフ数名〜十数名、購入登録は1日数件〜十数件程度の小規模運用と想定（2026年7月時点の公表料金に基づく概算）。

## 1. 想定利用量（月間）

| 項目 | 想定値 |
|---|---|
| ログイン回数 | 施設アカウント：月100回程度（共用端末で長期セッションのため頻度は低い） |
| 残額取得（GET /api/balance） | 1日50回×30日＝1,500回 |
| 購入登録（POST /api/purchases） | 1日10件×30日＝300件 |
| 履歴一覧取得（GET /api/purchases） | 1日30回×30日＝900回 |
| admin操作（残額修正・履歴編集削除） | 月20回程度 |
| レシート画像アップロード＆解析 | 購入の半数程度と仮定：月150件 |
| 画像1枚あたりサイズ | 圧縮後 目安1〜2MB |

## 2. Firebaseサービス別試算

Firebase Blazeプラン（従量課金）は無料枠（Sparkプランと同等の枠）を超えた分のみ課金される。

### 2.1 Cloud Functions（Hono実行環境）
- 無料枠：月200万回呼び出し、40万GB-秒、20万CPU-秒、5GB下り通信
- 想定呼び出し数：残額取得1,500 + 購入登録300 + 履歴一覧900 + admin操作20 + レシート解析150 ≈ **月3,000回程度**
- → **無料枠内に収まる（$0）**

### 2.2 Firestore
- 無料枠：1日50,000読み取り、20,000書き込み、20,000削除、1GB保存
- 想定：読み取り（残額取得+履歴一覧+解析結果確認等）月2,400回程度、書き込み（購入登録+admin操作）月320回程度
- 月換算しても1日あたりの無料枠（読み取り5万/日、書き込み2万/日）に遠く及ばない
- → **無料枠内に収まる（$0）**

### 2.3 Firebase Storage（レシート画像）
- 無料枠：5GB保存、1日1GBダウンロード（Sparkプラン基準）、Blazeでは超過分 $0.026/GB保存、$0.15/GBダウンロード
- 想定：月150件×1.5MB ≈ 225MB/月の新規保存。1年運用しても3GB弱で無料枠内
- → **ほぼ無料枠内に収まる（$0〜数十円/月）**

### 2.4 Firebase Hosting（SvelteKit静的配信）
- 無料枠：10GB保存、1日360MB転送
- SPA静的アセット（数MB程度）＋アクセス数が少ないため
- → **無料枠内に収まる（$0）**

### 2.5 Firebase Authentication
- Email/Password認証は無料（MAU課金はSMS認証等の一部機能のみ対象）
- → **$0**

### 2.6 Firebase Blazeプラン基本料金
- Blazeプラン自体に固定月額費用はなし（従量課金のみ）
- ただしBlazeプラン化には請求先アカウント（クレジットカード）の登録が必須（Cloud Functions・外部API呼び出しを使うため無料のSparkプランでは不可）

## 3. Gemini API（レシート画像解析）試算

- モデル：Gemini 2.5 Flash（画像解析用途として速度・コストのバランスが良い）
- 料金（2026年7月時点）：入力 $0.10 / 100万トークン、出力は別レート（テキスト生成分のみ、抽出結果は数百トークン程度と小さい）
- 画像1枚あたりのトークン数：解像度により数百〜1,000トークン程度（圧縮・リサイズ後を想定）
- 月150件処理と仮定：
  - 入力：150件 × 約1,000トークン ≈ 15万トークン/月 → $0.10 × 0.15 ≈ **$0.015/月**
  - 出力（解析結果JSON）：150件 × 約200トークン ≈ 3万トークン/月 → 出力単価を仮に$0.40/100万トークンとしても **$0.012/月**
- → **月あたり数十円程度、実質誤差レベルのコスト**
- 無料枠（Gemini APIには入力無料枠が存在する形態もある）を考慮すると、実運用ではほぼ$0に収まる可能性が高い

**注記**：Gemini APIの正確なレート制限・無料枠詳細は変動があるため、実装フェーズでGoogle AI Studio上の最新情報を確認し、想定外の高頻度アクセス（誤操作の連打等）に備えて6章で述べたソフトリミット（日次上限）を必ず実装すること。

## 5. コスト超過時のリスクと対策

- 万一、想定外のアクセス集中（悪意ある連打・スクリプト攻撃等）が発生した場合、Cloud Functions呼び出し数やGemini API呼び出し数が急増するリスクがある（セキュリティ設計書 T9/T10参照）。
- 対策：
  - Google Cloud側で**予算アラート**を設定し、想定額（例：月500円）を超えたら通知を受け取る。
  - Hono側でIPベースのレート制限・ログイン試行制限を実装（セキュリティ設計書2.2節）。
  - Gemini API呼び出しに日次上限（例：1日50回まで）のソフトリミットを設ける。
- これらの対策により、コスト超過のリスクは実質的に排除できる。
